# Dependency compatibility

Exact installed versions live in `package.json` and `bun.lock`. Prefer current compatible releases, including prereleases; upgrade coupled packages together. The constraints below explain pins rather than duplicate the package inventory.

Mise pins Bun for package management, tasks, and application tests, plus Node for the Vite/Vitest toolchain. This keeps a fresh checkout independent of a globally installed Node runtime.

- **Foldkit / Effect:** `foldkit@0.168.0`, `@foldkit/ui@0.168.0`, and the installed Vite/MCP integrations require Effect `4.0.0`; Foldkit also requires `@effect/platform-browser@4.0.0` exactly. Newer Effect patches alone do not satisfy those exact peers. `@effect/platform-bun` is Alchemy's Bun runtime peer; its `4.0.0` pin is the tested selection, not a requirement that every platform package share an identical version.
- **XState:** the selected line is `xstate@6.0.0-alpha.65` with `@xstate/effect@0.1.0-alpha.7`. The official bridge targets XState 6 and Effect 4. Check actual release versions; dist-tag names have previously pointed to older prereleases.
- **Alchemy compiler:** couple `alchemy` and `@alchemy.run/cloudflare-runtime` at `2.0.0-beta.81`. The Cloudflare runtime declares exact Rolldown peer `1.2.5`; the direct `rolldown` pin matches it. `scripts/build-worker.mjs` follows its [official Rolldown plugin example](https://github.com/alchemy-run/alchemy/blob/main/packages/cloudflare-runtime/src/rolldown/README.md). This checks standalone compilation, not a deployed Alchemy plan.
- **Pi:** keep `@earendil-works/pi-ai`, `@earendil-works/pi-durable`, and their Chord context dependency coordinated at `1.1.0`. The app imports Chord's official background context for durable conversation configuration. Pi's lazy OAuth registration requires the public `registerBunOAuthFlows()` adapter to make refresh modules reachable in the Worker bundle. Recheck development and production compilation plus local workerd behavior when upgrading Pi or Agents.
- **Workerd:** override to `1.20261006.1`, matching the exact runtime selected by the installed Miniflare/Wrangler test integration. Alchemy's bundled `1.20260918.1` rejects the application's `2026-10-08` compatibility date at actual dev startup: its newest supported date is `2026-09-25`. Remove this override when Alchemy selects a runtime supporting the application date; verify dev startup, runtime tests, and production bundling before removal. This override preserves the chosen compatibility behavior and existing local storage.
- **Runtime tests:** Cloudflare's Vitest integration runs inside workerd. Vitest 5's host filesystem module cache is disabled in `vitest.runtime.config.ts` because its cache files are unavailable inside that runtime. Keep this documented option until the integration supports that cache.
- **Development tools:** TypeScript 7 uses the official `@effect/tsgo` compiler patch and its installed configuration schema. The plugin configuration key remains `@effect/language-service`, as required by tsgo; the older package is not needed. shadcn is pinned locally so registry CLI and MCP use the same release. Foldkit dependency patches are version-specific; follow [their upgrade/removal criteria](../patches/README.md). Run the Effect compiler patch after compiler/toolchain upgrades.

## Workflow integration

The [version-matched XState Effect documentation](https://github.com/statelyai/xstate/blob/xstate%406.0.0-alpha.65/packages/xstate-effect/README.md) is authoritative for `setupEffect`, `fromEffect`, and `createEffectActor`. Ordinary XState `createActor` cannot host Effect actors. An application-scoped Effect Layer provides one actor to Foldkit resources; scope closure stops observation without undoing accepted remote work.

The bridge's `send` queues an event; it does not await a new snapshot. Commands and the snapshot Subscription therefore acknowledge the same request before releasing dispatch exclusion. Preserve this ordering contract when changing the integration and exercise its connected tests. No official combined Foldkit/XState adapter has been identified.
